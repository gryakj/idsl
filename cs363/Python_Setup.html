Python Environment Setup and Tutorial

Description

This documentation will help you configure a Python environment with optional GPU support.

Python Environment Setup

Machine learning projects implemented in PyTorch, TensorFlow, or JAX can greatly benefit from GPU acceleration. We recommend two online resources that provide both Python environments and free GPU resources: Kaggle and Google Colaboratory. However, if you already own GPU-backed hardware - either an Nvidia GPU or a Mac with an M-series processor and macOS Ventura (13.X) or later - and would prefer to work locally, we provide you with instructions for setting up a virtual environment.

Working remotely on Google Colaboratory

Google Colaboratory (Colab) is basically a combination of Jupyter notebook and Google Drive. It runs entirely in the cloud and comes preinstalled with many packages (e.g., PyTorch and TensorFlow) so everyone has access to the same dependencies. Even cooler is the fact that Colab benefits from free access to hardware accelerators like GPUs (K80, P100) and TPUs, Google’s proprietary ASICs.

Requirements. To use Colab, you must have a Google account with an associated Google Drive. Assuming you have both, you can connect Colab to your Drive with the following steps:

  1. From Google Drive, click the wheel in the top right corner and select Settings.
  2. Click on the Manage Apps tab.
  3. At the top, select Connect more apps which should bring up a GSuite Marketplace window.
  4. Search for Colab then click Add.

Workflow. If you don’t have one already, create a ZIP file containing all project-related Jupyter notebooks and/or Python starter code, then upload the existing or newly created ZIP file to Drive. You can then open any notebooks/source files in Colab and work on them, saving your progress back to Drive.

Best Practices. There are a few things you should be aware of when working with Colab. The first thing to note is that resources aren’t guaranteed (this is the price for being free). If you are idle for a certain amount of time or your total connection time exceeds the maximum allowed time (~12 hours), the Colab VM will disconnect. This means any unsaved progress will be lost. Thus, get into the habit of frequently saving your code whilst working on projects. To read more about resource limitations in Colab, read their FAQ here.

Using a GPU. Using a GPU is as simple as switching the runtime in Colab. Specifically, click Runtime -> Change runtime type -> Hardware Accelerator -> GPU and your Colab instance will automatically be backed by GPU compute.

Working remotely on Kaggle

Kaggle (also run by Google) is a longstanding website for data science competitions that also provides a Jupyter notebook environment with GPU/TPU hardware acceleration.

Requirements. To use Kaggle, you must: 1. Register for a Kaggle account using a valid email address. 2. Once logged in, verify your account using a phone number (you are only allowed to have one Kaggle account.)

Workflow. If you don’t have one already, create a ZIP file containing all project-related Jupyter notebooks and/or Python starter code. You can upload the ZIP file to Kaggle as a dataset by:

Adding Datasets

  1. In the left-hand navigation bar, click on Datasets, then click the button + New Dataset.
  2. Drag the zip file to the right-hand pane.
  3. Give the dataset a name, e.g., dataset-project0, in the Dataset Title field at the top.

Creating and Importing Notebooks

The creation of the dataset will enable you to access data files as well as Python starter code in files (.py) but not Jupyter notebook data. In order to create a Kaggle notebook from an existing Jupyter notebook: 1. In the left-hand navigation bar, click on Code, then click the button + New Notebook. 2. Click the autogenerated name at top to rename the notebook to something meaningful, e.g., Notebook-Project0. 3. In the notebook menu bar, click File -> Import Notebook. 4. Drag the provided project notebook to the right-hand pane, then click Import at the bottom.

Attaching Datasets and Importing Starter Code

The dataset you created previously, e.g., dataset-project0, needs to be added to the notebook so that it can be accessed. To do so, click on Add Input and then select the dataset from the list.

Once the dataset is attached, you must add the path to your notebook so that you can import the Python starter code. You can determine the local path by selecting a file in the attached dataset, and looking at the path to the right of the file’s name, e.g., /kaggle/input/dataset-project0/project0/util.py.

In your Jupyter notebook, add a cell at the top with the following commands, which must be edited to use the path you found above (without the name of the file):

import sys
sys.path.append('/kaggle/input/dataset-project0/project0/')

Best Practices. Kaggle will automatically save your Notebook as you work on it. As with Colab, Kaggle has resource limits, include 200 GB for Dataset, 20 GB for Notebook Data, and a maximum of 30 GPU hours per week. You can learn more about GPU resource limitations in Kaggle here.

Using a GPU. Using a GPU is as simple as switching the accelerator in Kaggle. Specifically, click Settings -> Accelerator and then select GPU P100, GPU T4, or TPU v3-8 and your Kaggle instance will automatically be backed by GPU compute. Please note that this will restart your notebook session and you will need to rerun all notebook cells run prior to switching.

If you’re interested in learning more about Kaggle, we encourage you to visit the resources below:

  • Documentation: Kaggle Notebooks
  • Documentation: Kaggle Datasets

Working locally on your machine

If you wish to work locally, you should use a virtual environment. You can install one via Anaconda (recommended) or via Python’s native venv module. Ensure you are using Python 3.8 - 3.12 as these versions are the ones currently supported by Pytorch.

Anaconda virtual environment

We strongly recommend using the free Anaconda Python distribution, which provides an easy way for you to handle package dependencies. Please be sure to download the Python 3 version, which currently installs Python 3.12.

Once you have Anaconda installed, it makes sense to create a virtual environment for the course. If you choose not to use a virtual environment (strongly not recommended!), it is up to you to make sure that all dependencies for the code are installed globally on your machine. To set up a virtual environment called cunyai, run the following in your terminal:

# this will create an anaconda environment
# called cunyai in 'path/to/anaconda3/envs/'
conda create -n cunyai python=3.12

To activate and enter the environment, run conda activate cunyai. To deactivate the environment, either run conda deactivate cunyai or exit the terminal. Note that every time you want to work on the project, you should rerun conda activate cunyai.

# sanity check that the path to the python
# binary matches that of the anaconda env
# after you activate it
which python
# for example, on my machine, this prints
# $ '/Users/gryakj/anaconda3/envs/sci/bin/python'

You may refer to this page for more detailed instructions on managing virtual environments with Anaconda.

Note: If you’ve chosen to go the Anaconda route, you can safely skip the next section and move straight to Installing Packages.

Python venv

As of 3.3, Python natively ships with a lightweight virtual environment module called venv. Each virtual environment packages its own independent set of installed Python packages that are isolated from system-wide Python packages and runs a Python version that matches that of the binary that was used to create it. To set up a virtual environment called cunyai, run the following in your terminal:

# this will create a virtual environment
# called cunyai in your home directory
python3.12 -m venv ~/cunyai

To activate and enter the environment, run source ~/cunyai/bin/activate. To deactivate the environment, either run deactivate or exit the terminal. Note that every time you want to work on the project, you should rerun source ~/cunyai/bin/activate.

# sanity check that the path to the python
# binary matches that of the virtual env
# after you activate it
which python
# for example, on my machine, this prints
# $ '/Users/gryakj/cunyai/bin/python'

Installing packages

Once you’ve setup and activated your virtual environment (via conda or venv), you should install the libraries needed to run the projects using pip. To do so, run:

# again, ensure your virtual env (either conda or venv)
# has been activated before running the commands below
cd project1  # cd to the project directory

# install project dependencies.
# since the virtual env is activated,
# this pip is associated with the
# python binary of the environment
pip install -r requirements.txt
